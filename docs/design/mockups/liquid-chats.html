Liquid: Chats (concept)

Revised: where Chats sit in the app, the chat list and the Inbox are now in the app's structure (ADR-0241), which also replaces this file's Page Chat panel with tabs side by side; this file keeps the conversation model.

A concept for the maintainer's direction recorded in ADR-0239, not yet for implementation: every conversation is a Chat, as in WhatsApp, one-to-one or a group, whether the others are people or agents. There are no agent sessions or projects beside it: an agent's work folder is a folder Source in the Workspace, and every Page has its own Chat, closed by default. Shell and wording follow the Pages mockups.

1 · The Chats list

"Chats" replaces "Agent sessions" in the sidebar and lists every Chat by latest activity, as WhatsApp and T3 Code do, one line each as dense as Notion's sidebar: its picture, its name, the time and unread messages; the last message shows in the Chat. An agent's picture is its mark, a person's their initial; a running agent shows a dot. + starts a Chat with one person or agent, or a group. Chats with people need accounts and sync and follow ADR-0236.

2 · A Page's Chat

"Chat" in the Page header, beside Arrange, opens the Page's own Chat at the side; it is closed by default and remembers whether it was open. Whoever joins it, person or agent, sees the Page as its context, and an agent's changes go through the Page's History. The Chat also appears in the list, named after its Page.

3 · An agent at work in a folder

The agent's work folder is the folder Source acme-api in the area Acme API, which Liquid only reads; the agent writes it through Meta-Harness. Approvals appear in the Chat, and each answer that changed files ends with its Diff and Trajectory, which open beside the Chat; they are details of an answer, no longer tabs of their own.

4 · An agent is a participant

A click on an agent's name shows its profile: the durable part, which outlives every Chat. It names its harness, model and instructions, its work folder and its rights, which a person grants (ADR-0223). A new Chat with the same agent starts a fresh history; branching from a message starts a new Chat.

Open before mockups for implementation

  1. Whether a Page's Chat is listed among all Chats or only on its Page.
  2. In a group with several people, an agent acts with the grant of the person who added it and the others propose (ADR-0232); how the Chat shows that.
  3. Where agents are created and their profiles edited: in Settings or from a Chat.
  4. How Diff and Trajectory open: beside the Chat, as here, or in the main area.
  5. Whether one agent can work in several Chats at once; in one folder this needs its own Git worktrees.
