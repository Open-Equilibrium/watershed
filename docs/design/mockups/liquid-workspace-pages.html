Liquid Workspace: Pages

Mockups for the M3a slice in PLAN.md, approved by the maintainer on 2026-11-01: the Explorer, a blank Page and its first actions, the built-in Blocks, Arrange mode, the PowerBar and a Source. They follow the V-Spec, ADR-0235 and guidelines.md. Page icons, Settings at the Explorer's foot and the PowerBar's prefixes were added on his request and approved the same day. Views, Connections and Automations are in the Blocks mockups, History and Roles in the History mockups.

1 · Explorer and a Page

The Explorer shows each area as a section, as Notion shows teamspaces. Pages nest; Sources sit among them as peers with a file or folder icon and open the same way. Agent sessions keep their approved place. Automations, History and Settings sit at the foot and open as dialogs over the current Page or Source; closing one shows it again. A Page that has never been arranged is one vertical flow at the 740 px reading width.

2 · A blank Page

A new Page opens with its title focused and one quiet line that names the first actions, so the empty Page explains itself. It has no type and no layout to choose. The Area's + creates it; the PowerBar and the Explorer's menu do too.

3 · Page icons

Every Page can have an icon, as in Notion and AppFlowy, but it sits beside the title in the title's size instead of above it, so the Page keeps its space for content: "Add icon" beside the title of a new Page, shown on hover, or a click on the icon opens the picker with Emoji and Icons tabs and a search. The icon appears in the Explorer, the breadcrumb, the PowerBar, mentions and Views on other Pages; without one, the plain Page symbol shows. Sources keep their file or folder symbol.

4 · The first action picks the Block

The same input always creates the same Block, so nobody has to choose a type first. Pasting a URL offers Notion's choice afterwards: keep the bookmark or turn it into an embed.

5 · The Block chooser

Typing / opens the chooser where the caret is, as in Notion and AppFlowy. "Existing Block…" adds a View of a Block from any Page; templates fill an empty Page with a starting composition.

6 · Text shortcuts

Notion's Markdown shortcuts set the current Text Block's formatting: #, ##, ### headings, - bullets, 1. numbers, [] to-dos, > a toggle, " a quote, **bold**, *italic*, `code` and @ a link to a Page or Block. A toggle is formatting, not a Block. Two shortcuts end the Section instead: --- starts a new Section below a divider (see the Section mockups), and ``` starts a Code Block, which ends the Section like any other Block type.

7 · The built-in Blocks

Seven Block types, each with a quiet header that names the Block, its View kind and its menu. The header shows only on hover or focus, except where a Block has a name.

8 · Arrange mode

"Arrange" in the Page header, or the PowerBar, switches the Page into Arrange mode. A 12-column grid appears; each Section of text and each other Block becomes a tile that moves by its top handle and resizes by its right edge in whole columns, and the selected tile shows its width. Arrow keys move the selected tile, ⌥ and the arrow keys resize it. Done or esc ends it. An arranged Page uses the main column's width, up to 1120 px; text inside a tile keeps the reading width.

9 · The same Page in a narrow window and on a phone

The order of Blocks is the same on every device. In a narrow window, tiles narrower than half the grid become half width and the rest full width. On a phone every Block stacks in Page order and stays visible; a Database, a Whiteboard and Code show a preview that opens a focused full-screen surface. Arrange mode on a phone starts with a long press.

10 · PowerBar

⌘K, or a tap of the Liquid key, opens the PowerBar over the current Page, as T3 Code's command palette works: one field and grouped results. Without a prefix it searches Pages, Sources, Blocks and text and jumps to the result, as ⌘P does in VS Code. / lists the Blocks to add to the current Page, as on the Page, and > lists only actions, as in T3 Code and VS Code. @ stays reserved for people, for chat after Release 1. It runs only actions the current Role allows; the footer names the prefixes.

11 · A Source

A Source opens like a Page. In M3a it is a local file or folder that Liquid reads but never writes (ADR-0235); Liquid rereads it when the file changes. "Use in a Block…" creates a Connection, and "Used by" lists them. The area's + menu adds it.

Decisions

Decided (ADR-0235)

  1. Areas are Explorer sections with nested Pages; Sources are peers in the same tree.
  2. M3a Sources are local files and folders, read-only.
  3. A pasted URL is a bookmark that fetches nothing; an embed loads only after a click.

Approved with these mockups (2026-11-01)

  1. The deterministic mapping of section 4, including a dropped CSV becoming a Database copy and ``` starting a Code Block.
  2. Database Views are Table, Board and Calendar; the Code Block shows code and never runs it.
  3. Arrange mode arranges Sections and other Blocks on 12 columns; narrow windows use half or full width; phones stack in Page order. An arranged Page widens to at most 1120 px.
  4. ⇧⌘N creates a new Page in the current area; ⌘N stays with agent sessions.

Added on request, approved the same day

  1. Page icons beside the title, with Emoji and Icons tabs; uploaded images come later.
  2. Automations, History and Settings sit together at the Explorer's foot and open as dialogs; Roles live in Settings.
  3. The PowerBar searches without a prefix and understands / and >; @ stays reserved for people; "Add Block" is gone from its list.
