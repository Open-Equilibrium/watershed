Checkpoints: approved mockups

Checkpoints of the Liquid Git slice in PLAN.md, following ADR-0234: a checkpoint at each turn's start and end, the Diff tab reading from them, a revert to before a turn, removal with the session and one action that removes all checkpoints. Layout, components and wording follow the agent surface mockups and guidelines.md. The maintainer approved them on 2026-11-01 with the decisions at the end.

1 · Diff tab shows one turn

The header names the turn shown and opens a menu of the session's turns, newest first, as T3 Code's Diff panel does (Latest turn, Turn n). A turn's changes run from its start checkpoint to its end checkpoint, so earlier turns stay visible after a restart. "All turns" compares the end of the latest turn with the start of the first. The revert action sits beside the menu and applies to the turn shown.

2 · A turn ends with its changes in the chat

Below a turn's last reply, one quiet row counts the turn's files and lines and offers both actions, with T3 Code's "changed files" wording and its "Open diff". It appears only once the turn's end checkpoint exists.

3 · Reverting to before a turn

The dialog lists every file that changes, including edits made outside the agent since then, and says what stays: commits, the branch and files Git ignores. T3 Code's dialog lists no files. Like T3 Code's "Edit from here", the session continues from before the turn with its prompt back in the input area, but on a new branch, so the undone turns stay in the session tree with their checkpoints.

4 · Refused while an agent runs in the checkout

Another session runs in the same folder, so the revert would change files under it. The dialog still lists the files, names the running session and keeps the action disabled until it stops; a session in another Liquid window is named but cannot be shown from here. T3 Code refuses every file revert outside its own worktree; Watershed refuses only while an agent runs there.

5 · Without checkpoints

The Diff tab says why it shows nothing, as T3 Code does for a folder without Git.

6 · Removing checkpoints

The project's menu in the sidebar removes all of Watershed's checkpoints in its repository; Git frees the space at its next cleanup. Deleting a session removes its checkpoints with it. T3 Code removes checkpoints only when a revert makes them obsolete.

Approved by the maintainer on 2026-11-01, with "Show the running session" dropped from section 4. The reviews of the revert found cases the sections above do not show. Files Git ignores are listed where a restored file needs their place, so "files Git ignores stay" becomes "other files Git ignores stay"; a path inside, at or above a repository in the project is listed but left alone; with only such paths the dialog says “No file reverts: a revert leaves repositories inside the project alone.”. Several running agents are counted. A turn that waits for another window's revert says so in the status bar, through the status entry extensions already use. 8 · Where a session is deleted

As in T3 Code's thread list and Notion's pages, a session's row opens a menu on right-click or from the "···" that shows on hover: in the sidebar for the open session and on the start page for each recent session. "Delete session…" opens the dialog of section 6. Deleting the open session stops its agent, starts a new session and then deletes the old one, as T3 Code moves on after deleting the active thread. Decisions

  1. A revert starts a new branch from before the turn and puts that turn's prompt back into the input area; the undone turns stay on their branch, rather than only reverting the files and telling the agent.
  2. The Diff menu offers "All turns" besides each turn.
  3. "Delete session" deletes the pi session file and its checkpoints after confirmation.
  4. "Remove all checkpoints" lives in the project's menu in the sidebar.
