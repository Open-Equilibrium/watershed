Liquid: session statistics

ADR-0279: the Trajectory goes; a session's statistics show only exact figures counted from its stored entries, as T3 Code's Usage counts provider history. Nothing is estimated or judged: tokens and cost are what pi recorded per response, times come from the turns' checkpoints and the extension's timing entries, and a tool call's outcome is its stored result. Interpretations come from an agent on request. The layout follows T3 Code: its thread details card holds the Git controls and the always-visible figures, its Usage page the detail.

1 · The session card, top right

T3 Code's thread details card, rebuilt for a Liquid session. The Chat keeps its tab; the branch, pull request, Git action and Changes leave the header and the Diff tab for the card, in T3 Code's rows and order: the branch with its commits ahead opens the branch menu, the pull request row shows its state and checks, the split button runs the next Git step with the other steps behind its arrow, and Changes counts the shown turn's lines and opens the Diff (section 2). Below a divider, the session's figures read label, hairline, value, as T3 Code's usage and context rows: the context bar fills toward the model's window with a tick where pi compacts, and tokens, working time and tool calls show their parts as one segmented hairline. Hovering a row explains it. The sliders button at the end of the header shows or hides the card; it sits beside the reading column when the window is wide enough, otherwise it opens as a popover (section 5).

2 · Changes opens the Diff beside the Chat

As in T3 Code, the Diff opens in a panel at the right of the Chat, from the card's Changes row or with ⌘D (T3 Code's key), and closes with ✕ or ⌘D again. It keeps everything the Diff tab does today: the turn menu (T), unified or split (U), whitespace (W), the file list and reverting. With the panel open the Chat is narrower, so the card moves into its popover.

3 · Statistics, opened from the card

The card's Statistics row (⌘U, T3 Code's Usage key) opens a panel at the same corner, laid out like T3 Code's Usage for one session: the headline figure with its parts on the left, a chart on the right, then totals, share bars and a breakdown. T3 Code charts by day; a session charts by turn, the unit the Chat and the Diff already use. Cost and Tokens split by model, as T3 Code splits by provider. The breakdown adds what T3 Code has no view for: tool calls, each with its outcomes as a segmented bar sized by its count. Hovering a column or a bar shows its exact figures; Escape closes the panel.

4 · Time, and the breakdown by turn

Time is the view T3 Code lacks. Working time adds up each turn from its start to its end checkpoint and splits into waiting for the model and running tools, as the extension's timing entries record them; what is left of the turn is Other. The turn breakdown lists every prompt with its time, tokens and cost, and its failed tool calls; selecting a row scrolls the Chat to that turn.

5 · While a turn runs, older sessions, narrow windows, choosing rows

While a turn runs, the figures grow as entries are stored; open tool calls show as running (hatched), not yet as an outcome. A response pi recorded without a cost adds tokens but no cost, and the cost row's ⓘ says how many. A session from before the timing entries shows a dash for model and tool time, never a guess. In a narrow window the sliders button opens the same card as a popover below it. Right-clicking the card chooses its rows, as in T3 Code; hidden rows keep their shortcuts.

6 · Branching without the Trajectory (decision)

Today “Continue from here” exists only in the Trajectory. T3 Code forks a thread at a selected turn. Recommended: an agent answer's ··· menu in the Chat offers “Branch from here”, which continues the same session from that answer, as the Chats concept already decided (“Branching from an agent's answer makes a branch within the same Chat”). The Chat's branch mark stays as it is.

Questions

  1. Show the context row, context used against the model's window with pi's compaction point (recommended, as T3 Code), or leave it out, since ADR-0279 names tokens, cost, time and tool calls only?
  2. Keep the extension's timing entries for model and tool time (recommended), or drop them and show working time only?
  3. “Branch from here” in an agent answer's menu (recommended), or drop branching with the Trajectory?
  4. Whole session only, as the status bar counts (recommended), or a switch between this branch and all branches?
  5. The tokens' data colors fail the colorblind check in their order (data-1 next to data-2: blue and purple merge for red-blind readers). This mockup uses the order data-1, data-3, data-2 and keeps gaps and legends. Swap data-2 and data-3 in tokens.css (recommended), or keep the order and rely on gaps and labels?
