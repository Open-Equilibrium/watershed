Liquid Workspace: Blocks

Mockups for the M3a slice in PLAN.md, approved by the maintainer on 2026-11-01: synchronized Views over one Block, copying, the deletion cascade, Connections and formulas, and Automations. They follow the V-Spec, ADR-0235 and guidelines.md; the shell is the one in the Pages mockups.

1 · One Block, two Views

"Expenses" is one Database Block shown on two Pages: as a table on Household budget and as a board on Monthly review. Editing either changes both. The header says it is synced and where else it appears, as Notion's synced blocks do. The Block's menu holds Add to Page, Duplicate and both ways to remove it.

2 · Copy, paste and Add to Page

Pasting a copied Block creates an independent copy (ADR-0235); a chip right after the paste offers "Paste as View" instead, as Notion offers choices after a paste. "Add to Page…" in the Block menu, and "Existing Block…" in the chooser, add a View on purpose.

3 · Removing a View, and deleting the last one

"Remove from this Page" on a Block that has other Views takes away only this View, with no dialog. Removing the last View deletes the Block, so the menu then says "Delete". Without dependents it deletes at once and offers Undo. With dependents a dialog lists the impact first: Connections and the Block's own Automations go with it, Automations of the Workspace that use it turn off and need attention. All of it is one Action in History, and one revert brings it back. "Delete everywhere…" does the same from any View.

4 · Connections

A Connection is created where data is needed: the Chart's panel picks its data from a Database or a Source. The panel lists what the Block uses and what uses it. Placing Blocks side by side never connects them.

5 · Formulas

Formulas use Excel's function names (ADR-0235). Typing a name suggests Blocks, fields and functions; a chosen reference becomes a chip bound to the Block's ID, so renaming "Expenses" changes the chip, not the result. A Database formula field uses the same language over its own row. A reference to a deleted Block shows why it fails.

6 · Automations

"Automations" at the Explorer's foot opens a dialog over the current Page that lists every Automation; closing it shows the Page again. It lists those that belong to a Block and are deleted with it, and those of the Workspace. M3a Automations start when a row is added, a field changes or a button is clicked (ADR-0235); each runs as the Role it is assigned.

7 · An Automation reads as a sentence

The editor builds a sentence, as Trello's Butler rules read: When, If, Then. Each part is a token that opens a short list. The Role it runs as shows whether it allows every action; Test runs it once on the last row and records the result in History like any run.

8 · Needs attention

An Automation of the Workspace whose Block was deleted turns off and says why. Choosing another Block repairs it; reverting the deletion in History turns it back on.

Decisions

Decided (V-Spec, ADR-0235)

  1. Removing the last View deletes the Block, its Connections and its own Automations in one revertible Action; Automations of the Workspace that use it turn off and need attention. There is no Trash.
  2. Pasting a copied Block creates a copy; a View is always explicit.
  3. Formulas use Excel function names with references as chips bound to stable IDs; Automations read as sentences and start on events and buttons.

Approved with these mockups (2026-11-01)

  1. The synced marker "Synced · on 2 Pages" with the other Pages on hover.
  2. Block menu: Add to Page, Duplicate, Copy, Copy link to Block, Move to, Protect, Block history, Remove from this Page (Delete when it is the last View) and Delete everywhere.
  3. Deleting without dependents needs no dialog and offers Undo; with dependents a dialog lists them.
  4. A Connection is made in the panel of the Block that needs the data; the panel lists "Uses" and "Used by".
  5. M3a Automation actions: change a field, add a row, create a Page from a template and show a notification.

Added on request, for review

  1. Automations open as a dialog over the current Page or Source, with the editor inside it; closing it returns there.
