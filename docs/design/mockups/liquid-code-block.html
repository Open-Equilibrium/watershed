Liquid Workspace: Code Block

Mockups for the Code Block, the first of the other built-in Blocks in PLAN.md. They detail the Code Block of the approved Pages mockups (sections 4, 6 and 7): ``` starts it, it ends a Section like any other Block type, and it shows code but never runs it; Apps that run code come with M3b. The frame and the slash commands follow the Table View mockups. Proposed for approval; the open questions are at the end.

1 · Code on a Page

A Code Block shows its code in the monospace font on the code background, with syntax colors from the tokens. Hovering over it or focusing it shows a quiet header: the language, which opens the language picker, and Copy. No line numbers, as in Notion. The code is edited in place: a click puts the caret there.

2 · Adding a Code Block

Slash commands list Code next to Table under Blocks. Typing ``` at the start of a Text Block does the same, as in Notion: the Text Block becomes a Code Block, any text after the caret becoming its code. The new Code Block is in Plain text, with the caret in it. It splits the Section it lands in (Sections mockups).

3 · Choosing the language

The language in the header opens a picker with a search field, as Notion's does: typing filters, ↑↓ choose, ⏎ takes the language and esc closes it. The chosen one has a check. The language is stored with the Block, so Markdown export writes it after the ```. Which languages the list offers depends on the highlighter (open question 1).

4 · Editing

⏎ starts a new line with the same indentation; ⇥ and ⇧⇥ indent and outdent the line or every selected line by two spaces. Long lines do not wrap: the code scrolls sideways inside the Block, as a wide table does. Copy puts the code on the clipboard and turns into a check for a moment, as T3 Code's copy button does.

5 · Next to a Code Block

The caret enters and leaves the code as it does other text: ↑ at the start of the Text Block below goes to the code's last line, ↓ on the code's last line to the start of the Text Block below. ⌫ at the start of the Text Block below joins nothing, and a numbered list after it starts at 1 again, as after a table. ⌫ in an empty Code Block turns it back into an empty Text Block, as in Notion. A Liquid version without Code Blocks shows one as the placeholder of ADR-0245.

6 · Keyboard

KeyIn a Code Block
⏎New line, keeping the current line's indentation
⇥ ⇧⇥Indent or outdent the line, or every selected line, by two spaces
↑ on the first line, ← at the startGo to the end of the Text Block above, if any
↓ on the last line, → at the endGo to the start of the Text Block below, if any
escLeave the Block; the caret goes to the start of the Text Block below it, if any, as from a table
⌫ in an empty Code BlockTurn it into an empty Text Block
⌘ASelect all of the Block's code

Decisions

Proposed with these mockups

  1. The core stores a Code Block's text and its language name, Plain text when none; a Code Block's text has the Text Block's cap of 1,000,000 characters (ADR-0251), and each edit is one write, as a Text Block's is.
  2. The header, the picker, Copy and the keys as sections 1 to 6 show; no line numbers, no wrapping and no running.
  3. / lists Code under Blocks beside Table; ``` at a Text Block's start turns it into a Code Block, as in Notion.
  4. Pasted code arrives as text, as today; recognizing code on the clipboard (Pages mockups, section 4) follows later, since Flutter's clipboard reads plain text only and telling code apart needs a native clipboard package.
  5. On a phone, a Code Block shows a preview that opens a focused full-screen surface, as already approved; that comes with the phone client.

Open questions

  1. Highlighter. Which code colors the code? A · Liquid's own highlighter, which the Diff panel uses today (diff_lines.dart). Pro: no new dependency; one look for code across Liquid. Con: the same few rules for every language (comments, strings, keywords, numbers); the language picker only labels the code and sets the export's language. B · re_highlight or flutter_highlighting, Dart ports of highlight.js. Pro: rules for about 190 languages. Con: a new dependency; re_highlight has had no release in about two years. C · shiki_flutter, a Dart port of Shiki, which T3 Code uses. Pro: TextMate grammars, the same as VS Code and T3 Code. Con: a new, younger dependency, and grammars to ship in the app. Recommendation: A now, since the stored language lets B or C follow without changing any data; the Diff panel would then gain from the same choice.
  2. Long code. How tall is a Code Block with many lines? A · As tall as its code, as in Notion and on GitHub. Pro: the code reads as part of the Page. Con: a very long Block lays out every line, and long Pages slow down. B · Up to 24 lines, then it scrolls inside, as a table keeps a fixed height (section 4). Pro: one bounded height, as the Table View decided; scrolling stays with the Page. Con: a long listing needs scrolling in two places. Recommendation: B, for the same reason the Table View chose a fixed height; Arrange mode can change it later.
