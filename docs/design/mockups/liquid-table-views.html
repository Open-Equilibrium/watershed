Liquid: Tables and their Views

For the slice in PLAN.md, after ADR-0309. A Table holds the data and lives in the sidebar. What sits on a Page is always a View of it, with its own title, sort and filter.

1 · A View on a Page, and Tables in the sidebar

The block has one title, the View's. The note on the right always names the Table. The sidebar's Tables section lists every Table in the Workspace, whichever area it belongs to.

2 · The note on the right, Sort and Filter below

Sort and Filter sit on the line below the title, and each shows what it holds. Several sorts or filters show the first and a count, such as “+1”. A click opens its editor.

With nothing set

3 · Editing the View's title

A click on the title changes this View only. The Table is renamed on its own page (section 4). A new Table starts with the first title typed as its name too; after that the two are separate.

4 · Opening a Table from the sidebar

It shows all rows and where the Table is shown. A click on a column's name sorts by it, a second click reverses that, a third clears it; the search field keeps the rows that contain its text. Neither is saved: both clear when the page is left. A click on the title renames the Table; its ··· menu holds Delete Table….

5 · Adding a View

The slash command Table makes a new Table with its first View; Existing Table… picks one. A View starts with no sort or filter, and can copy them once from a View the person has access to. The two stay independent afterwards. If the Table has no other View, the question is skipped.

6 · Deleting

Deleting a View while the Table has others on Pages asks nothing. Deleting the last one asks whether the Table goes too; kept, it stays in Tables. Every deletion is one Action that a revert restores.

Delete Table… from the sidebar

7 · When a View cannot show its Table

The View stays with its title. Without access, the note does not reveal the Table's name.

Decisions for this mockup

  1. Sorting and searching on a Table's page: cleared when the page is left (recommended), or saved for everyone? Saved, the page would need its own setup, like a View.
  2. In a View too: does a click on a column's name set the View's sort, and does a View get the same search field, also not saved (both recommended)?
