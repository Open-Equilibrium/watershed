2 · A failed save shows inside Settings

Since the save channel was unified, a failed save of Appearance, Diff or Shortcuts reaches only the status bar, which Settings hide. Proposal: one notice at the top of the Settings content, whichever section is open, fed by that channel. It shows the latest failure, keeps the change in use, and stays until ✕, esc or the next successful save of the same settings. The Liquid key's problem keeps its own notice inside Shortcuts.

5 · Choosing a pull request's base searches GitHub

Today the base dialog lists the target repository's first 500 branches and filters them; a branch beyond them is taken only as typed and checked later. Proposal: the list still opens with those branches, and typing also asks GitHub for matching branch names after a short pause, so every branch can be found; the field says while it searches. A typed name that GitHub does not know is refused, not taken.

Decisions

  1. The ··· sits inside the row for the session card and Page rows alike, and replaces the status word while shown (decided 2026-11-11).
  2. A failed save shows as one notice on top of the Settings content, in the danger colors (decided 2026-11-11).
  3. The range handles work as a two-thumb slider with the keys and announced text drawn in section 3 (decided 2026-11-11).
  4. Below 760 px window height the comparison shows its metrics in one line (decided 2026-11-11).
  5. The base dialog searches GitHub as the person types, refuses names GitHub does not know and keeps today's behavior when the search fails (decided 2026-11-11).
  6. “Export record” writes the folder to Downloads and shows it in Finder, without a save dialog (decided 2026-11-11).
