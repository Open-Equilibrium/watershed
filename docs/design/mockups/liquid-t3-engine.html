Liquid on T3 Code: mockups

Step 2 of the T3 track. T3 Code takes over checkpoints, diff, revert, Git actions, pull requests and worktrees with its behavior as shipped (ADR-0282); Liquid keeps its layout (ADR-0287) and changes only what T3's behavior changes. Labels are T3 Code's own. One writer model writes commit messages, pull request text and thread titles (ADR-0294). Names, numbers and paths are examples. Approved 2026-11-15: build it exactly as T3 Code's desktop app does, with its flows and labels, including “Publish repository” and “Checkout PR” where T3's protocol carries them; where this drawing and T3 differ, T3 wins.

1 · Session card: Git rows and the next Git step

The rows stay. The branch row opens T3's ref picker (section 4). A pull request row appears once T3 links one to the thread, with its state; clicking it opens the pull request in the browser. The split button shows T3's quick action for the branch's state; its arrow lists T3's actions, disabled ones with T3's reason. There is no Fetch: T3 fetches in the background. The statistics rows show what T3 reports (ADR-0293).

T3's dialog. The message is optional: left empty, the writer model writes it. Files are all selected; Edit lets the person exclude some. “Commit on new branch” creates a branch named by the writer model and commits there. No checkpoint attribution and no branch-name field: T3 has neither.

3 · Pull requests

“Create PR” and “Commit, push & PR” run at once: the writer model writes the title and description, and T3 picks the base. There is no pull request dialog, no base choice and no draft switch; the person edits the pull request on GitHub. T3 links it to the thread, and the session card shows it (section 1). Hosts other than GitHub work as far as T3 supports them.

4 · Branch picker

T3's ref picker in the branch row's menu. Switching runs Git's checkout as is: changes that fit come along, otherwise Git's message shows and nothing switches. Liquid offers no stash. A branch checked out in another worktree moves the session there, as in T3. While the agent runs, switching is disabled.

6 · Edit from here, and Fork from this response

T3's rollback replaces Revert and Branch from here. On a prompt, “Edit from here” rewinds the session to before it and returns the prompt to the input area; the later turns leave the session. “Revert files too” also restores the files, but only in a session with its own worktree; in Current checkout that button is missing and T3 rewinds the conversation only. The turn footer's “Revert files to before this turn…” opens the same dialog. On an answer, “Fork from this response” starts a new session from there, in the sidebar; it replaces session branches.
