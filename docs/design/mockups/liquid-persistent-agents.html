Persistent agents in Liquid

Liquid's screens for Agent profiles (ADR-0283), after Grok Bot, Muse, Dots and Duet: you make and change an agent by writing to it, and its settings stay visible and editable in the session card. The agent Chat itself stays T3's; these screens add only what T3 lacks.

A · Sidebar and an agent's Chat

An Agents section sits above Threads. Each row shows the agent's state, in the words the session rows use, or when it next wakes up. Selecting an agent opens its current thread in the usual Chat. The session card gains an Agent section above T3's Automations, which list the agent's routines; each setting is edited where it is shown.

B · A new agent starts as a Chat

+ beside Agents opens an empty agent Chat: project, model and permission mode are picked in the composer as for a new thread, the mode starting at Approval required, so an agent that is not watched asks before it acts. Starters fill the composer, as Grok's templates do. The first message is the job.

C · The agent configures itself, visibly

After the first message the agent names itself, saves its instructions and sets its routines; each change is a line in the Chat with Open or Undo, and a routine has Run now, as Grok Bot shows routine and setting events in its transcript. Later changes work the same way: “also on Sundays”, “stop the digest”, “be shorter”.

  • Instructions live as instructions.md in the agent's memory folder, beside its notes: the agent and you edit the same file. Routines by chat use T3's own schedule_task tool, which binds them to the agent's thread, so they move with it at 80%.
  • Undo reverts that one change: the routine is deleted, or the instructions go back to the version before. Model and permission mode change only by hand in the card: an agent never raises its own permissions.
  • The agent row's menu (⋯) has Remove agent…. Its confirmation says that the routines end and that the memory folder stays.
  • Earlier threads opens the agent's previous threads read-only, newest first, as T3 lists a thread's forks.
  • A webhook URL reaches only this host, because T3 listens on loopback. Public URLs come with host links through the Liquid account (ADR-0285), as does sharing an agent with a team (ADR-0283).
